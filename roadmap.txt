I actually think abandoning a full rewrite is the right move.

From what I saw, your current project already has the hard part done:

* Voice input
* Voice output
* LLM integration
* Tool execution
* Desktop control
* Memory
* GUI

Most people spend months getting to that point.

The fastest path to a genuinely impressive Entity is to **evolve the current architecture**, not replace it.

---

# The North Star

Before the roadmap, I think it's important to define what we're building.

Current Entity:

```text
User
 ↓
LLM
 ↓
Action
 ↓
Tool
```

Target Entity:

```text
User
 ↓
Planner
 ↓
Task List
 ↓
Reasoner
 ↓
Tool Execution
 ↓
Verification
 ↓
Correction
 ↓
Completion
```

That single change unlocks everything else.

Priority:
⭐⭐⭐⭐⭐⭐⭐⭐⭐⭐

Impact:
Massive

Difficulty:
Medium

---

Current:


# PHASE 2 — Tool Registry

Priority:
⭐⭐⭐⭐⭐⭐⭐⭐⭐

Impact:
Huge

Difficulty:
Easy

---

Current:

```python
if action == "open_app":
```

Every tool requires modifying router.

---

Replace with:

```python
TOOLS = {
    "open_app": open_app,
    "search_web": search_web,
    "lock_pc": lock_pc
}
```

---

Then planner simply says:

```json
{
    "tool": "open_app"
}
```

---

Benefits:

* Infinite scalability
* Cleaner code
* Easier debugging

# What We Should Do First

I would not touch vision.

I would not touch memory.

I would not touch agents.

The single highest-return upgrade is:

### 1. Planner

### 2. Executor

### 3. Verification Loop

Those three components transform Entity from:

```text
Command Executor
```

into

```text
Task Solver
```

Everything else becomes easier afterward.

So the next thing I would do is design the **planner architecture around your existing `brain.py` and `router.py`**, rather than creating new disconnected files. That way we can upgrade the current codebase without breaking what already works.
